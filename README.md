# AXIOS Demo (Build #1)

Кликабельный демо-прототип мобильного веб-приложения для связки **СТО ↔ Автовладелец**.

## Что это

Это **Demo Mode**:
- без реальных SMS, платежей, карт и внешних интеграций;
- все данные моковые и хранятся в `localStorage` браузера;
- API-слой реализован в `src/mockApi.js` с искусственной задержкой.

## Технологии

- Vite-style lightweight scaffold (dev/build scripts на Node)
- Vanilla SPA + роутинг через History API
- TailwindCSS (CDN)
- Mock API + `localStorage`

## Запуск

```bash
npm install
npm run dev
```

Приложение поднимется на `http://localhost:5173`.

Сборка production-артефактов:

```bash
npm run build
```

Проверка линта (в текущем scaffold — no-op):

```bash
npm run lint
```

## Демо-флоу

1. Откройте `/auth`
2. Введите телефон и любой 4-значный код
3. На `/role` выберите роль:
   - **Автовладелец**: поиск СТО, карточка СТО, отправка заявок, статусы
   - **СТО**: профиль, окна на день, входящие заявки (подтвердить/уточнить/отклонить)

## Seed-данные

При первом запуске автоматически сидируются:
- 10 СТО в кластерах Подольск и Солнцево/Переделкино/Внуково;
- окна приёма на сегодня/завтра (и часть на послезавтра);
- базовые фото/описания/способы оплаты.

Если нужно начать с чистого состояния — очистите `localStorage` в браузере.

## Реализовано в Build #1

- Demo auth по телефону
- Выбор роли и route guards
- Клиентские экраны:
  - поиск СТО + фильтр "сегодня/24ч"
  - карточка СТО + окна приёма
  - создание заявки
  - список заявок со статусами
- СТО-экраны:
  - профиль СТО
  - управление окнами (день): добавить/удалить
  - входящие заявки: подтвердить/уточнить/отклонить
- Мини-метрики доверия:
  - `avgResponseMin`
  - `confirmRate`
  - бейджи "Быстро отвечает" / "Надежно подтверждает"

## Ограничения

Не входит в Build #1:
- реальные интеграции,
- платежи,
- рейтинги/отзывы,
- склад/финансы/заказ-наряды,
- сложный планировщик (неделя/месяц).


## Build #2 demo-готовность

### Demo Panel
- Откройте `/demo` для операций демо-оператора.
- Доступны кнопки:
  - `Reset demo data` (очистка демо-данных + повторный seed),
  - `Login as Client` / `Login as STO` (быстрые входы),
  - `Use fixed date` (стабильные today/tomorrow для демонстрации),
  - `Export events` (выгрузка event log в JSON).

### Готовые сценарии
- `Scenario: срочно шиномонтаж`
- `Scenario: заявка ждёт ответа`
- `Scenario: needs_info`

### Как сбросить демо
1. Откройте `/demo`.
2. Нажмите `Reset demo data`.
3. При необходимости снова выберите fixed date и сценарий.

## Build #3: pilot polish (шаг 30)

### Как провести пилот-демо за 1–2 минуты

Быстрый тайминг для интервью/показа:

1. Откройте `/demo` и нажмите `Reset demo data`.
2. Нажмите `Login as STO` и перейдите на `/sto/windows`.
3. Проверьте, что на сегодня есть хотя бы одно окно (или добавьте одно окно).
4. Вернитесь в `/demo`, нажмите `Login as Client`.
5. Откройте `/client/search` и включите фильтр «Есть окна сегодня».
6. Откройте карточку СТО и нажмите `Запросить это окно`.
7. Заполните заявку и отправьте её.
8. Для проверки подтверждения **без риска рассинхронизации роли/СТО** используйте `/demo` → `Scenario: заявка ждёт ответа` и подтвердите её на `/sto/requests`.

> Почему так: сценарий `Scenario: заявка ждёт ответа` создаёт заявку в нужную СТО-сессию, поэтому кнопка `Подтвердить` гарантированно доступна в smoke-прогоне.
>
> Цель smoke-потока: от входа до подтверждения заявки пройти без ручной очистки данных и без «мертвых» экранов.

- СТО-флоу «входящие заявки → подтвердить» работает.


## Build #4: заказ-наряды (демо)

### Как протестировать отправку наряда

1. Зайдите как СТО и откройте `/sto/requests`.
2. Для подтверждённой заявки нажмите `Создать заказ-наряд`.
3. На `/sto/workorder/:id` добавьте 1–2 позиции (работы/запчасти).
4. В блоке `Отправка клиенту` используйте любой канал:
   - `Скопировать ссылку`,
   - `Поделиться` (Web Share API),
   - Telegram / WhatsApp / Email.
5. Откройте публичную ссылку вида `/o/:token` и проверьте view-only страницу.

> Важно: это demo-режим. Фактической отправки сообщений/писем нет — используются только share/deep-link механики браузера.
> `Печать / PDF` на публичной странице использует обычный `window.print()`.
